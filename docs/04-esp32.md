# 04 — Clients ESP32

## Rôle

Chaque ESP32 se connecte au Wi-Fi local, s'abonne à **une** carte (un chemin), reçoit le flux et
le joue sur sa sortie I2S (DAC / ampli). Il n'envoie pas d'audio : session **réception seule**.

## Transport principal : WebRTC + signalisation WHEP

```text
ESP32                                        Antenne (http://<pc>:8080)
  | POST /whep/carte1                                 |
  |   Content-Type: application/sdp                   |
  |   offre SDP : audio recvonly, Opus et/ou PCMU     |
  |-------------------------------------------------->|
  | 201 Created                                       |
  |   Location: /whep/carte1/<session>                |
  |   réponse SDP : audio sendonly, codec de la carte |
  |<--------------------------------------------------|
  |        ICE (UDP, LAN) → DTLS → SRTP               |
  |<========= RTP audio, une trame / 10 ms ===========|
  | DELETE /whep/carte1/<session>   (fin de session)  |
```

- Le **chemin** (`path` dans `[[card]]`) détermine la carte écoutée : c'est l'« adresse WebRTC »
  configurable par carte.
- Le **codec** est imposé par la carte (`encoding`) ; l'offre de l'ESP32 doit le proposer.
- Côté serveur, aujourd'hui, `POST <path>` valide la requête puis répond `501` (jalon 3).

### Côté ESP32 : ce qu'on sait d'ESP-WebRTC (Espressif)

D'après la page produit Espressif : signalisation intégrée **OpenAI, WHIP, AppRTC, KVS, Janus**
et **signalisation personnalisée** ; codecs audio **G.711 A/µ et Opus** ; cartes de référence
ESP32-P4 et ESP32-S3 (Korvo). **WHEP n'est pas listé** : il faudra soit écrire une petite
signalisation personnalisée « WHEP » (POST de l'offre, lecture de la réponse — très proche de
WHIP), soit adapter Antenne à un protocole déjà supporté.

À vérifier dans le code d'`esp-webrtc-solution` (jalon 4) :

- [ ] mode réception seule (recvonly) sans micro ;
- [ ] décodage Opus stéréo en temps réel sur la puce retenue (S3 recommandé, P4 confortable) ;
- [ ] mémoire nécessaire (DTLS + SRTP + tampon de gigue) → PSRAM probablement requise ;
- [ ] taille du tampon de gigue réglable (latence).

## Transports de repli

| Transport | Latence | Complexité ESP32 | Usage |
|-----------|---------|------------------|-------|
| **WebRTC / WHEP** | basse | élevée (ICE, DTLS, SRTP) | cible principale |
| **RTP / UDP direct** (Opus ou PCMU, sans chiffrement) | la plus basse | faible : un socket UDP + décodeur | plan B si WebRTC est trop lourd ; à ajouter au jalon 3 bis 🔶 |
| **HTTP WAV** (`/stream/<id>`) | haute (tampons HTTP) | faible | debug uniquement |

## Choix du codec par carte

| Codec | Débit | Charge de décodage | Quand l'utiliser |
|-------|-------|--------------------|------------------|
| Opus 10 ms, 48 kHz | 32–128 kb/s | moyenne | défaut ; musique ; stéréo |
| G.711 µ-law / A-law | 64 kb/s, 8 kHz mono | très faible | voix, annonces, ESP32 classique |
| PCM16 | 768 kb/s (mono 48 kHz) | nulle | RTP L16 / debug, hors WebRTC standard |
